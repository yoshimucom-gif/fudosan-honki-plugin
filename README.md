# 不動産 訪問査定申込（本気査定）WordPressプラグイン

売却を本気で検討している方向けの査定申込フォーム。**お名前・電話番号まで受け取り**、
受付完了メールを自動返信＋担当者へ通知する。査定額の自動表示は行わない（受付のみ）。

匿名査定プラグイン（`fudosan-satei`）／査定書作成受付（`fudosan-sateisho`）の姉妹版。
3つとも同じサイトで併用でき、メニュー・DBテーブル・設定はすべて独立している。

| プラグイン | 取得する情報 | 価格の表示 |
|---|---|---|
| かんたん不動産AI査定 `fudosan-satei` | メールのみ | 統計から参考価格レンジを即時表示 |
| 査定書作成受付 `fudosan-sateisho` | メールのみ | 表示しない（後日、査定書を送付） |
| **訪問査定申込 `fudosan-honki`（本リポジトリ）** | **お名前・電話番号まで** | 表示しない（担当者が個別に対応） |

## 中心機能：項目ごとの 必須／任意／非表示

すべての入力項目はスキーマ（`fhs_customer_fields()` / `fhs_situation_fields()` /
`fhs_property_fields()`）で定義され、設定画面「入力項目」タブから1項目ずつ
**必須 / 任意 / 非表示** を切り替えられる。保存キーは `mode_<group>_<key>`。

常に必須（切り替え不可）＝ メールアドレス・物件種別・物件住所・同意チェック。

項目を追加するときはスキーマに1行足すだけでよい。フォーム描画・検証・
メール文面・DB保存・CSV・設定画面のすべてがスキーマから自動生成される。
`'col'` を指定した項目は専用カラムに、`null` の項目は `details` にまとめて保存される
（`fhs_ensure_columns()` が起動時に不足カラムを自動追加する）。

## 構成

```
fudosan-honki-wp/
├── fudosan-honki/
│   ├── fudosan-honki.php        本体（設定・AJAX・ショートコード）
│   ├── includes/plugin-updater.php  自動更新チェッカー
│   └── readme.txt               利用者向け説明
├── build.py                     バージョン更新＋zip再生成
├── update.json                  自動更新の配信情報
└── fudosan-honki.zip            配布本体（build.py が生成）
```

- 識別子: 定数 `FHS_*` / 関数 `fhs_*` / CSS `fhs-*` / テーブル `wp_fudosan_honki_leads`
- ショートコード: `[fudosan_honki]`（`design="compact" | "card" | "teaser" | "teaser-v"`、`button="..."`）
- 通信: `admin-ajax.php` 経由（SiteGuard等でREST APIが無効な環境でも動く）

## ティザー（記事に置く入口フォーム）

```
[fudosan_honki design="teaser"   url="/satei/"]   横長（記事の途中・記事末）
[fudosan_honki design="teaser-v" url="/satei/"]   縦・幅440px（サイドバー）
```

2〜3項目だけ聞いて査定ページへ送る。物件種別は**タイルを1タップ**で選ぶ形（セレクトより離脱が少ない）。
`fields` で聞く項目と順番を指定（`ptype` / `address` / `survey` / `purpose` / `timing`）。
`title` `subtitle` `badge` `steps` `logo` `note` `button` で見せ方を調整できる。

**引き継ぎは `sessionStorage`（同一タブ）で行い、URLのクエリには一切載せない。**
物件住所という個人に結びつく情報をURLに置くと、ブラウザ履歴や外部サイトへのリファラに残るため。
サーバー側でHTMLに焼き込む方式も採らない（ページキャッシュが効くと「最初に開いた人の入力値」が
他の訪問者に配られる）。**お名前・電話番号・メールはティザーに置けない仕様**にしている
（個人情報は、利用目的の明示と同意チェックがある本フォームでのみ受け取る）。

遷移先では引き継いだ値を復元し、種別グループを開き、「↓ 続きはこちらから（あとN項目）」の
バナーを出して最初の未入力欄までスクロールする。申し込み完了時に引き継ぎデータを破棄する。

## リリース手順

```
py build.py 1.0.1 "・○○を修正"
git add -A && git commit -m "v1.0.1" && git push
```

push すると `raw.githubusercontent.com` の `update.json` が更新され、
プラグインを入れた全サイトの管理画面に「更新可能」バッジが出る。

※ 更新通知は「インストール中のバージョン < GitHub のバージョン」のときだけ出る。
   反映は WP管理→ダッシュボード→更新→「もう一度確認します」で手動チェック
   （既定は最大12時間の遅延。GitHub raw のCDN反映にも数分かかる）。

## 法務まわりの前提（重要）

- ミカタ株式会社は**宅地建物取引業者ではない**。よって「価格査定」と呼ばず
  **「参考価格の情報提供」**とし、「当社は宅地建物取引業者ではなく、売買の媒介・代理は行いません」を明示する。
- 免責文はメールテンプレートの**外**から常時付加される（`fhs_with_disclaimer()`）。
  管理画面で本文を書き換えても消えない。
- **氏名・電話番号を取得するため、匿名査定より個人情報保護法の義務が重い。**
  設定「個人情報」タブの第三者提供スイッチをONにすると、利用目的と同意文に
  提供先が明記され、同意チェックが27条の同意を兼ねる。**OFFのまま他社に渡すのは違法。**
- 営業案内メールは同意チェックのあったお客様にのみ（特定電子メール法）。
  担当者通知メールには毎回「営業連絡の可否」を明記している。
- 公開前に弁護士等の確認を推奨。

## 実装上の既知の罠（先行2プラグインで踏んだもの・対策済み）

- `dbDelta` は「1カラム1行」でないと既存テーブルへのカラム追加を取りこぼす → `fhs_ensure_columns()` で明示ALTER
- カラム長超過で `$wpdb->insert` が失敗し、リードが消える → `fhs_trim_len()`
- `admin-ajax` は失敗時に `-1`/`0` を返し JSON として解釈できてしまう → 応答の形を検証してから完了画面を出す
- レート制限を検証より前に置くと、入力ミスした正規のお客様がブロックされる → 検証成功後に計数
- オプションのチェックボックスを `fhs_opt($k,'1')` で読むと OFF にできない → `fhs_flag()`（`array_key_exists` 判定）
- `label for` が固定idだと、同一ページに2つ置いたとき2つ目のチェックが押せない → `$uid` で一意化
- `type="number"` は全角数字を打つと値が空になる → `type="text" + inputmode` にして PHP 側で半角化
- ブラウザバックで種別が復元されても `change` は発火しない → `pageshow` と遅延実行で再反映
